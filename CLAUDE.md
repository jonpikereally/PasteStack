# PasteStack

A local, native macOS clipboard manager (menu-bar app, card-wall picker,
pinboards, OCR search, catch-all app-data capture). Plain Swift + AppKit +
SwiftUI, zero dependencies. Requires macOS 13+ and Xcode Command Line Tools
(`xcode-select --install`) — full Xcode NOT needed.

## If the user asks to install/set up PasteStack

1. Build: `./build.sh` (compiles with swiftc directly — do NOT use `swift build`;
   Sources/PasteStack/Version.swift is generated by the script and gitignored,
   so it won't exist in a fresh clone until the script runs).
2. Install: copy the bundle out of any cloud-synced folder — apps often fail to
   launch from Dropbox/iCloud paths ("application is not open anymore"):
   `ditto --norsrc PasteStack.app ~/Applications/PasteStack.app && codesign --force --sign - ~/Applications/PasteStack.app`
3. Have the user launch it via Finder/Spotlight (`open` can fail with error
   -600 from embedded terminals).
4. Tell the user to grant Accessibility when prompted (System Settings →
   Privacy & Security → Accessibility) — required for auto-paste (simulated
   ⌘V). The menu-bar dropdown shows live status ("Auto-paste: ✓ enabled").

## Known traps

- The app is ad-hoc signed: after every REBUILD, macOS silently invalidates
  the Accessibility grant while the Settings toggle still shows enabled.
  Fix: `tccutil reset Accessibility com.jonpike.pastestack`, relaunch, re-grant.
  Toggling the switch off/on is NOT sufficient.
- First screenshot after enabling "Copy New Screenshots to Clipboard" triggers
  a Desktop folder access prompt — expected, allow it.
- Usage: ⇧⌘V opens the card wall; ←/→ + ↩ paste (⇧↩ plain text); double-click
  pastes; right-click a card for pinboards / paste-as-image / delete.
- All data stays local in ~/Library/Application Support/PasteStack.
- Releases: bump VERSION, run `UPDATE_NOTES="…" ./release.sh`, then commit
  and push. release.sh writes a universal build to updates/PasteStack.zip and
  updates/latest.json; every installed copy's updater reads latest.json from
  raw.githubusercontent.com (main branch). raw.githubusercontent.com can cache
  for about 5 minutes, so a fresh release may not be seen immediately.
  `./build.sh` alone is a local build and does NOT publish anything.
- The updater's swap script runs `tccutil reset` itself, so after an in-app
  update the user only has to re-grant Accessibility when prompted.
- Info.plist lives in Resources/ and is copied into the bundle by the scripts;
  PasteStack.app/ is build output (gitignored).
